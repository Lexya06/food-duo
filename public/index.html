Наглядный отчет и интерактивные тесты соответствия каждому пункту задания.

1. Мгновенная синхронизация через WebSockets

Позиции камеры участников, перемещение диких животных (20 Гц), смена раундов, снимки и вспышки передаются всем подключенным клиентам в режиме реального времени.

Протокол: Native WebSocket (ws) Частота синхронизации: 20 fps
✅ Выполнено

2. Только JavaScript, без фреймворков

Frontend написан на чистом Vanilla JavaScript (ES6+ модули, Canvas API, Web Audio API). Backend — чистый Node.js без Express, React, Vue, Angular или Next.js.

Frontend: Vanilla JS + Canvas Backend: Node.js (http + ws)
✅ Выполнено

3. Сохранение данных между запусками

Все профили игроков, рекорды, фотоальбом и история матчей сохраняются в файле data/database.json с атомарной перезаписью (atomic write). Данные сохраняются при перезапуске сервера.

⭐ 8-10: Выполнено

4. Конкурентный доступ и разрешение конфликтов

Реализовано два уровня разрешения конфликтов:
А) Конкурентный снимок цели: При одновременном нажатии кнопки съемки арбитр с микросекундной точностью (process.hrtime.bigint) и учетом точности центрирования определяет победителя (Золото) и ассистента (Серебро).
Б) Совместное редактирование карточек: При одновременной правке карточки несколькими пользователями сервер применяет оптимистическую блокировку (OCC по версии version) и 3-Way Field Merge, объединяя непересекающиеся поля без потери данных.

⭐ 8-10: Выполнено

5. Восстановление при потере соединения

При отключении сети клиент сохраняет состояние в localStorage, буферизирует действия в очередь (Offline Action Queue) и периодически пытается переподключиться. Сервер удерживает сессию в течение grace-периода и восстанавливает игрока без потери очков.

⭐ 8-10: Выполнено

6. Готовность к развертыванию на хостинге

Приложение полностью автономно, слушает process.env.PORT, снабжено Dockerfile и конфигурацией render.yaml для развертывания на Render, Glitch или Railway в 1 клик.
